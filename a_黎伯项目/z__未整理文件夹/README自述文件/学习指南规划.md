## 三、第二阶段：核心模块精读（建议3天）

### 原则

> **按数据流向顺序精读**：先读产生数据的（规划器），再读消费数据的（控制器），最后读硬件交互的（驱动），不按目录顺序随机跳读。

---

### 第5步：xline_path_planner（路径规划器）精读

**为什么第一个精读**：它是整个系统的入口，决定了"机器人要走什么路线"

**精读顺序**：按 6 阶段流水线的顺序读

| 顺序 | 文件 | 精读要点 | 大约时间 |
|------|------|----------|----------|
| 5.1 | `include/xline_path_planner/common_types.hpp` | 所有数据结构的定义，这是整个系统的词汇表 | 30分钟 |
| 5.2 | `src/cad_parser.cpp` | DXF→JSON 的解析逻辑，单位换算机制 | 40分钟 |
| 5.3 | `src/geometry_preprocessor.cpp` | Polyline拆分、共线合并、路径扩展 | 20分钟 |
| 5.4 | `src/grid_map_generator.cpp` | Bresenham光栅化、De Casteljau算法 | 30分钟 |
| 5.5 | `src/path_planner.cpp` ★★ | 贝塞尔转场、贪心排序、路径偏移 | 60分钟 |
| 5.6 | `src/trajectory_generator.cpp` | 路径点→ExecutionNode 的转换 | 20分钟 |
| 5.7 | `src/output_formatter.cpp` | JSON输出格式 | 15分钟 |
| 5.8 | `src/main.cpp` | 规划器的节点入口，串联所有阶段 | 20分钟 |

**为每个关键文件记录的要点**：

```
【文件】: src/path_planner.cpp
【功能】: 路径规划主类，生成绘图路径+转场路径
【输入】: CADData (解析后的几何数据)
【输出】: RouteSegment[] (带喷墨模式/打印机类型/步进电机控制的路径段)
【核心方法】:
  - plan_paths()             主入口
  - processGeometryGroup()   贪心排序+逐个规划
  - planGeometryPath()       单条绘图路径
  - planConnectionPath()     贝塞尔转场路径
  - generate_cubic_bezier_transition()  三次贝塞尔
  - generate_quintic_bezier_transition() 五次贝塞尔(曲率连续)
【关键算法】:
  - 贪心搜索: findNearestUnprocessedLine()
  - 贝塞尔曲线: De Casteljau求值
  - 路径偏移: applyPathOffset()
【依赖】: common_types.hpp, GridMapGenerator, CollinearMerger
【配置文件】: bezier_transition 段（控制点比例、曲率约束、大角度增强等）
```

### 第8步：xline_follow_controller 精读

**为什么第四个精读**：它是运动控制的核心算法包

| 顺序 | 文件 | 精读要点 | 大约时间 |
|------|------|----------|----------|
| 8.1 | `include/xline_follow_controller/common/follow_common.hpp` ★★ | HampelFilter, SavitzkyGolayFilter, PIDController, SecondOrderSmoother, FourthOrderLowpassFilter — 全部滤波器和控制器 | 60分钟 |
| 8.2 | `include/xline_follow_controller/common/base_follow_controller.hpp` | 控制器统一接口（多态基类） | 15分钟 |
| 8.3 | `include/xline_follow_controller/line_follow/line_follow_controller.hpp` + `.cpp` | 直线跟随的状态机和Sigmoid速度曲线 | 40分钟 |
| 8.4 | `include/xline_follow_controller/rpp_follow/rpp_follow_controller.hpp` + `.cpp` | RPP算法的完整实现 | 50分钟 |

- RPP的 `getLookAheadDistance()` → `pruneGlobalPlan()` → `getLookAheadPoint()` 三步调用链

### 第9步：跨模块追踪一条完整执行链路

**目标**：通过追踪一条完整的直线执行来串联所有模块

**追踪路径**：

```
用户点击执行
  → xline_server execution_events.py: execute_plan事件处理器
    → calibration → 成功
    → 逐条下发
      → motion_control_center.cpp: handleGoal() → execute()
        → extractLineData() 解析JSON
        → line_follow_controller_.setPlan()
        → while (!isGoalReached()):
            → compute_velocity()
              → line_follow_controller.cpp: computeVelocityCommands()
                → PID + Hampel + SavitzkyGolay + SecondOrderSmoother
                → return cmd_vel
            → publish cmd_vel
        → wheels_driver: cmd_vel_callback() → control_loop()
          → 逆运动学: v,ω → RPM_left, RPM_right
          → iwmc_servo_control.set_target_velocity_rpm()
          → slcan_comm.sdo_write() → CAN → 伺服轮执行
          → 编码器反馈 → publish odom
```

**操作方法**：用IDE的"查找引用"和"跳转到定义"功能，一步步从上层追踪到最底层。

**验收标准**：能对着代码逐步解释从"点击执行"到"电机转动"的完整调用链。
