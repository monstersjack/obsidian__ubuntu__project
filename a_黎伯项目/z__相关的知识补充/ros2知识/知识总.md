### 重要知识点总结

ip -br address：以简洁格式显示本机网卡和 IP，确认网卡位于喷码器所在网段。

ifconfig 是 Linux 中用于查看和配置网络接口的命令，
ipconfig 是 Windows 系统用于查看和管理网络配置的命令


###  can通信


命令说明：

- `sudo ip link set can0 down`：先关闭已有的 `can0` 接口，避免重复配置时报错。
- `sudo ip link set can0 type can bitrate 1000000 restart-ms 100`：设置 CAN 波特率为
  `1 Mbit/s`，并在总线进入 `BUS-OFF` 后允许 100 ms 自动恢复。
- `sudo ip link set can0 up`：重新启用配置完成的 CAN 接口。
- `ip -details -statistics link show can0`：查看接口状态、波特率、错误计数和收发统计。

正常时应看到接口为 `UP`，CAN 状态为 `ERROR-ACTIVE`。如果没有 `can0`，先检查
内核/设备树和 CAN 收发器；如果是 `BUS-OFF`，先检查波特率、线序、供电和终端电阻，
不要继续启动轮驱。

只读观察总线帧（系统已安装 `can-utils` 时）：

```bash
timeout 3s candump can0
```

#####  1. `can0`：当前使用的 CAN 接口

```text
can0: flags=193<UP,RUNNING,NOARP> mtu 16
```

| 字段 | 含义 |
|---|---|
| `can0` | Linux 中的第一个 CAN 网络接口 |
| `UP` | 接口已经启用 |
| `RUNNING` | 接口正在工作 |
| `NOARP` | CAN 不使用以太网 ARP，这是正常的 |
| `mtu 16` | CAN 接口的最大帧长度，属于正常值 |
| `txqueuelen 10` | 发送队列长度为 10 |

因此，`can0` 目前是启用状态，轮子驱动使用的就是它。

#####  2. `can0` 的接收数据

```text
RX packets 2751185  bytes 22009480 (22.0 MB)
RX errors 0  dropped 846354  overruns 0  frame 0
```

含义：

- `RX packets 2751185`：已经接收到约 275 万个 CAN 数据包。
- `bytes 22009480`：接收数据约 22 MB。
- `RX errors 0`：没有检测到 CAN 帧格式错误。
- `dropped 846354`：有约 84 万个数据包被丢弃。
- `overruns 0`：没有硬件接收溢出。
- `frame 0`：没有帧格式错误。

这里需要重点注意：

```text
dropped 846354
```

相对于接收总包数约为 **30.8%**，这个数值偏高。它不一定表示 CAN 线本身错误，也可能是：

- 应用程序读取 CAN 数据不够及时；
- 内核接收队列溢出；
- CAN 总线数据量过大；
- 驱动或过滤规则处理不及时。

建议持续观察：

```bash
watch -n 1 'ip -details -statistics link show can0'
```

并监听实际 CAN 帧：

```bash
timeout 10s candump can0
```

#####  3. `can0` 的发送数据

```text
TX packets 468821  bytes 3750568 (3.7 MB)
TX errors 0  dropped 0
```

含义：

- `TX packets 468821`：已经发送约 46 万个 CAN 数据包。
- `TX bytes 3750568`：发送数据约 3.7 MB。
- `TX errors 0`：发送没有错误。
- `dropped 0`：没有发送数据丢失。
- `carrier 0`：CAN 不使用以太网载波，这里为 0 正常。
- `collisions 0`：没有以太网碰撞，CAN 接口中通常为 0。

发送方向目前看起来正常。

#####  4. `can1`

```text
can1: flags=193<UP,RUNNING,NOARP> mtu 16
RX packets 0
TX packets 0
```

`can1` 是第二个 CAN 接口，目前虽然已经启用，但没有收发任何数据。

这通常表示：

- 当前车辆使用的是 `can0`；
- `can1` 没有接入 CAN 总线；
- `can1` 是板卡上的备用 CAN 控制器。

因为配置是：

```yaml
can_interface: can0
```

所以 `can1` 没有数据并不影响当前轮子驱动。

#####  5. `enP4p65s0`：有线网卡

```text
inet 192.168.0.100
netmask 255.255.255.0
broadcast 192.168.0.255
```

这是当前有线网络接口：

- 本机 IP：`192.168.0.100`
- 子网掩码：`255.255.255.0`
- 所在网段：`192.168.0.0/24`
- 广播地址：`192.168.0.255`

它很可能用于连接：

- LN150 全站仪：`192.168.0.1`
- 中间喷码器：`192.168.0.10`

截图中它的收发数据都不为零，说明有线网卡正在工作。

#####  6. `enP3p49s0`

```text
flags=4099<UP,BROADCAST,MULTICAST>
RX packets 0
TX packets 0
```

这个网口被系统启用了，但没有接收到任何数据，也没有 IP 地址。通常表示：

- 没有插网线；
- 网线另一端设备未连接；
- 网口没有建立物理链路。

它不是当前主要使用的有线网口。

#####  7. `lo`：本机回环接口

```text
lo: flags=73<UP,LOOPBACK,RUNNING>
inet 127.0.0.1
```

这是 Linux 的本机回环接口：

```text
127.0.0.1
```

用于本机==程序之间通信==，例如：

- 本机 Foxglove Bridge；
- 本机 ROS 2 节点；
- 本机服务测试。

它不是物理网卡，收发数据很多是正常的。

#####  8. `wlp2p33s0`：无线网卡

```text
inet 192.168.123.57
netmask 255.255.255.0
```

这是无线网卡：

- 无线 IP：`192.168.123.57`
- 无线网段：`192.168.123.0/24`

它与有线网卡的 `192.168.0.0/24` 是不同网段。访问 LN150 或喷码器时，通常应使用有线网卡 `enP4p65s0`，避免路由走错。

#####  总体判断

目前可以得出：

```text
can0：已启用，正在通信，发送正常，但接收丢包数偏高
can1：已启用，但没有使用
enP4p65s0：192.168.0.100，有线网络正常
enP3p49s0：没有建立有效网络通信
lo：本机回环，正常
wlp2p33s0：无线网络正常
```

最需要继续排查的是：

```text
can0 的 RX dropped = 846354
```
