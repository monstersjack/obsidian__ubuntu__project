# 轮子上位机测试命令

本文记录通过 Ubuntu 的 `can0` 使用 `cansend` 控制 M1505A/B 轮毂电机的测试命令。

当前小车轮子 ID 和方向定义：

```text
ID1 = 右轮
ID2 = 左轮

小车前进 = ID1 正转，ID2 反转
小车后退 = ID1 反转，ID2 正转
```

轮子反馈 ID：

```text
ID1 右轮反馈 = 0x97
ID2 左轮反馈 = 0x98

反馈帧最后 1 字节：
02 = 速度环
01 = 电流环
00 = 电压开环
```

速度换算：

```text
10RPM = 0x0064
30RPM = 0x012C
60RPM = 0x0258

-10RPM = 0xFF9C
-30RPM = 0xFED4
-60RPM = 0xFDA8
```

`0x32` 控制帧数据含义：

```text
032# ID1高 ID1低  ID2高 ID2低  ID3高 ID3低  ID4高 ID4低
```

例如：

```bash
# ID1 = +30RPM，ID2 = -30RPM
cansend can0 032#012CFED400000000
```

## 一、CAN 初始化

每次测试前建议先执行一次：

```bash
# 关闭 can0
sudo ip link set can0 down

# 设置 can0 波特率为 1Mbps，并开启自动恢复
sudo ip link set can0 type can bitrate 1000000 restart-ms 100

# 启动 can0
sudo ip link set can0 up

# 查看 can0 状态
ip -details link show can0
```

正常状态应看到：

```text
can state ERROR-ACTIVE
bitrate 1000000
```

## 二、监听反馈

另开一个终端监听：

```bash
candump can0
```

正常两个轮子都在线时，应能看到：

```text
can0 097 [8] ... 02
can0 098 [8] ... 02
```

其中：

```text
097 = ID1 右轮
098 = ID2 左轮
02 = 当前处于速度环模式
```

## 三、基础初始化命令

```bash
# 停止所有电机，确保测试从静止开始
cansend can0 032#0000000000000000
sleep 0.5

# 使能 ID1 右轮 和 ID2 左轮
# 0A = 使能
cansend can0 105#0A0A000000000000
sleep 0.2

# 设置 ID1 右轮 和 ID2 左轮为速度环模式
# 02 = 速度环
cansend can0 105#0202000000000000
sleep 0.2

# 设置 ID1 右轮 和 ID2 左轮主动反馈周期为 10ms
# 0A = 10ms 主动反馈
cansend can0 106#0A0A000000000000
sleep 0.5
```

## 四、查询模式命令

查询模式用于主动查询轮子的速度、位置、故障码、当前模式。

查询目标含义：

```text
01 = 查询速度
02 = 查询母线电流
03 = 查询绕组温度
04 = 查询位置
05 = 查询故障码
06 = 查询当前模式
```

### 1. 设置 ID1 右轮为查询反馈方式

```bash
# 0x106 中 ID1 对应第 1 个字节
# 80 = 查询反馈方式
cansend can0 106#8000000000000000
```

### 2. 查询 ID1 右轮状态

```bash
# 查询 ID1 的速度、位置、故障码，自定义标记 A1
cansend can0 107#01010405A1000000

# 查询 ID1 的当前模式、速度、位置，自定义标记 A1
cansend can0 107#01060104A1000000

# 查询 ID1 的母线电流、绕组温度、故障码，自定义标记 A1
cansend can0 107#01020305A1000000
```

正常应收到：

```text
can0 097 [8] ...
```

### 3. 设置 ID2 左轮为查询反馈方式

```bash
# 0x106 中 ID2 对应第 2 个字节
# 80 = 查询反馈方式
cansend can0 106#0080000000000000
```

### 4. 查询 ID2 左轮状态

```bash
# 查询 ID2 的速度、位置、故障码，自定义标记 A2
cansend can0 107#02010405A2000000

# 查询 ID2 的当前模式、速度、位置，自定义标记 A2
cansend can0 107#02060104A2000000

# 查询 ID2 的母线电流、绕组温度、故障码，自定义标记 A2
cansend can0 107#02020305A2000000
```

正常应收到：

```text
can0 098 [8] ...
```

### 5. 恢复主动反馈 10ms

查询结束后，如果想恢复两个轮子的主动反馈：

```bash
# ID1 和 ID2 都恢复 10ms 主动反馈
cansend can0 106#0A0A000000000000
```

## 五、慢速测试：10RPM，每个动作持续 10 秒


## 九、刷 ID 命令

注意：

```text
刷 ID 时总线上只能接一只电机。
刷 ID 前必须让电机失能。
每次上电只支持设置一次 ID。
设置成功后建议断电重启电机。
```

### 1. 把当前唯一接入的电机设置为 ID1

```bash
# 全部失能
cansend can0 105#0909090909090909
sleep 0.5

# 设置当前电机 ID = 1
cansend can0 108#0100000000000000
sleep 1

# 断电重启电机后，查看是否出现 097
candump can0
```

### 2. 把当前唯一接入的电机设置为 ID2

```bash
# 全部失能
cansend can0 105#0909090909090909
sleep 0.5

# 设置当前电机 ID = 2
cansend can0 108#0200000000000000
sleep 1

# 断电重启电机后，查看是否出现 098
candump can0
```

## 十、常见问题排查

### 1. `cansend` 提示 `Wrong CAN-frame format`

原因通常是 CAN ID 写错。`cansend` 标准帧 ID 要写 3 位十六进制。

错误写法：

```bash
cansend can0 32#012C012C00000000
```

正确写法：

```bash
cansend can0 032#012C012C00000000
```

### 2. 只有 `098`，没有 `097`

说明当前只看到 ID2 左轮反馈，没有看到 ID1 右轮反馈。需要检查右轮：

```text
1. 右轮 24V 是否接好
2. 右轮 CAN_H / CAN_L 是否接好
3. CAN_H / CAN_L 是否接反
4. 非隔离 CAN 模块是否和 24V 电源负极共地
5. 右轮是否真的刷成了 ID1
```

### 3. `write: No buffer space available`

通常说明 CAN 总线没有正常 ACK，可能是：

```text
1. 目标电机没有上电
2. CAN_H / CAN_L 没接好
3. CAN_H / CAN_L 接反
4. 没有共地
5. 总线终端电阻不合适
6. can0 进入异常状态
```

恢复 can0：

```bash
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000 restart-ms 100
sudo ip link set can0 txqueuelen 1000
sudo ip link set can0 up
ip -details link show can0
```

### 4. 判断是否处于速度环

监听：

```bash
candump can0
```

如果反馈最后一个字节是：

```text
02 = 速度环，可以用 RPM 命令控制
01 = 电流环，此时 0x32 数据不是 RPM，而是电流给定
00 = 电压开环
```

所以运动测试前一定要执行：

```bash
cansend can0 105#0202000000000000
```

并确认反馈最后一位为 `02`。
