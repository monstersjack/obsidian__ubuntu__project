### 一句话总链

`CAD/移动端` → 转换后的图纸 JSON → `xline_path_planner` 的 `plan_path` 服务或 `xline_server` 的 `/plan` 轻量规划 → 计划 JSON 文件 → Socket.IO `execute_plan` → ROS Action `execute_plan` → 跟随控制器计算速度 → `/task_cmd_vel` → `xline_cmd_vel_mux` → `/cmd_vel` → `wheels_driver` → 电机。全站仪和 IMU 经 `xline_localization` 反馈 `/robot_pose`；喷码由运动控制中心在执行过程中调用打印服务。

> [!warning] 同名“规划”不是同一个算法
> `xline_path_planner` 的 `plan_path` 是 ROS 服务，处理 CAD 几何、路径与转场等；`xline_server/services/planning_service.py` 的 `plan_path()` 是 Python 函数，仅对 `selected=true` 的已有线条做贪心排序。不能把后者说成调用了前者，也不能假定每次执行都经过两个规划器。

### 按包找文件

| 包或模块 | 主入口与核心文件 | 在划线链中的职责 |
| --- | --- | --- |
| `xline_cad` | 从实际界面入口追至导出/上传实现 | 图纸编辑与文件生成；具体上传路径以界面代码为准 |
| `xline_mobile` | `lib/modules/task/widgets/cad_detail_page.dart`、`core/clients/websocket/websocket_client.dart` | 选计划、发 `execute_plan`、显示状态 |
| `xline_server` | `api/planning.py`、`services/planning_service.py`、`communications/websocket/execution_events.py`、`services/execution_manager.py` | 保存计划、逐条下发 Action、汇总结果 |
| `xline_path_planner` | `src/main.cpp`、`src/cad_parser.cpp`、`src/geometry_preprocessor.cpp`、`src/collinear_merger.cpp`、`src/path_planner.cpp`、`src/trajectory_generator.cpp`、`src/output_formatter.cpp` | 解析 CAD、整理几何、排序/转场、生成执行 JSON |
| `xline_msgs` | `src/xline_msgs/action/ExecutePlan.action`、`srv/*.srv` | 定义 Action 与喷码/电机等服务契约 |
| `xline_base_controller` | `src/motion_control_center.cpp`、`src/inkjet_client.cpp` | 接收 Action，按线型选择控制器，发布任务速度并协调喷码 |
| `xline_follow_controller` | `src/line_follow/line_follow_controller.cpp`、`src/rpp_follow/rpp_follow_controller.cpp`、其他曲线/圆策略 | 根据目标轨迹和位姿计算速度；不是独立转发速度的 ROS 节点 |
| `xline_cmd_vel_mux` | `xline_cmd_vel_mux/cmd_vel_mux.py` | 汇合任务/平板速度并依据障碍信息限速，发布最终速度 |
| `wheels_driver` | `wheels_driver/run_motor.py`、`wheels_driver/iwmc_servo_control.py` | 差速逆运动学、超时停车、驱动左右伺服轮 |
| `xline_ln150_driver` | `src/lndriver_node.cpp` | 发布棱镜坐标 `/reflector_position` |
| `beiwei_imu_driver` | `src/beiwei_imu_driver.cpp`、`src/imu_parser.cpp` | 发布 IMU 数据，供定位使用 |
| `xline_localization` | `src/localization_node.cpp` | 融合棱镜和 IMU，发布 `/robot_pose` |
| `lslidar_driver` | 驱动入口及配置 | 提供激光扫描给障碍检测 |
| `xline_obstacle_detector` | `src/obstacle_detector_node.cpp` | 由 LaserScan 生成障碍距离和状态 |
| `xline_inkjet_printer` | `xline_inkjet_printer/inkjet_client_node.py`、`msg_encoder.py` | 将打印服务请求转换为喷码机协议 |
| `stepper_motor_driver` | 驱动节点与服务定义 | 左/右喷头关联的步进电机控制；触发条件见运动控制中心 |

上表是阅读索引，不代表所有包在每套启动方式中均已启动。尤其 `xline_follow_controller` 是被运动控制中心调用的算法库；阅读时先确认调用位置，再找算法实现。

### 每层要看什么

| 层 | 关键数据 | 常见误解 |
| --- | --- | --- |
| 图纸 | 原始 CAD 单位、图层、线型、选中标记 | CAD 毫米不能直接当 ROS 米 |
| 规划 | 起终点、画线/转场、喷头、顺序 | 转场移动不等于喷墨画线 |
| 执行 | `plan_json`、`plan_uid`、`current_id` | Socket.IO 事件不等于 ROS Action 本身 |
| 控制 | `/robot_pose`、横向误差、航向误差、线/角速度 | 跟随控制器算速度，不直接写 CAN |
| 底盘 | `/task_cmd_vel`、`/cmd_vel`、左右轮 RPM | 发布任务速度不等于电机已收到最终速度 |
| 喷码 | `start_print`、`stop_print`、打印服务 | 控制器标记与打印机物理响应存在通信延迟 |

### 版本核对点

| 源码现象 | 阅读结论 |
| --- | --- |
| `planner.yaml` 的 TCP 监听地址仍为 `192.168.0.123` | 这是仓库配置，不应误写成当前小车 `192.168.0.100` 的已运行地址 |
| `xline_base_controller` 实际发布 `/task_cmd_vel` | 日志文字已同步修正；最终 `/cmd_vel` 由速度仲裁器发布 |
| `planning_service.py` 的排序按当前点到线段两端的距离做贪心选择 | 它不做 CAD 几何离散或全局最短路线保证 |
| `main.cpp` 中规划起点的位姿超时判断被暂时关闭 | 配置里的 `pose_timeout_sec` 不代表此版本会拒绝旧位姿 |
