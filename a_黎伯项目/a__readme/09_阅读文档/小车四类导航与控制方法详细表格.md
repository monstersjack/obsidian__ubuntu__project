### 小车四类导航与控制方法详细表格

本文把最近讨论的四个主题统一整理：

| 主题编号 | 主题 | 解决的问题 | 主要输出 |
|---:|---|---|---|
| 1 | 角速度产生与调整 | 小车应该以多快的速度转向 | `Twist.angular.z` |
| 2 | 两点无障碍导航 | 小车如何从起点到终点 | 目标航向、线速度、角速度 |
| 3 | 航向纠正 | 小车如何知道自己是否走偏或转偏 | `robot_pose.yaw`、航向误差 |
| 4 | 速度仲裁与命令链路 | 多个速度来源如何安全地输出到轮驱 | `/cmd_vel` |

### 一、角速度产生与调整方法

#### 1. RPP / Pure Pursuit 曲率法

| 项目 | 详细说明 |
|---|---|
| 核心思想 | 选择路径前方的前瞻点，根据当前位置到前瞻点的曲率计算转向 |
| 主要输入 | 当前位姿、前瞻点、线速度、路径曲率 |
| 主要公式 | `angular.z = linear.x × curvature` |
| 调大什么会更快转向 | 增大曲率、减小前瞻距离、增大线速度 |
| 相关配置 | `lookahead.min_dist`、`lookahead.max_dist`、`velocity.angular.max` |
| 适合场景 | 曲线、圆形、连续路径 |
| 优点 | 轨迹平滑，适合复杂路线 |
| 风险 | 前瞻距离过小会抖动，过大会转向滞后 |
| 原项目位置 | `xline_follow_controller/src/rpp_follow/` |

#### 2. 航向误差比例控制

| 项目 | 详细说明 |
|---|---|
| 核心思想 | 目标航向与当前航向的差值越大，输出角速度越大 |
| 主要输入 | 目标航向、当前 IMU 或 `robot_pose` 航向 |
| 主要公式 | `angular.z = K_yaw × yaw_error` |
| 调大什么会更快转向 | 增大 `K_yaw` |
| 适合场景 | 直线起步、航向微调、目标角度对准 |
| 优点 | 实现简单，响应直接 |
| 风险 | 只看航向时不能修正横向位置偏差 |
| 调参建议 | 先小幅增大比例增益，观察是否出现左右摆动 |
| 原项目相关配置 | `line.yaml` 的 `heading_pid` 和 `phase` 参数 |

#### 3. 横向误差 PID

| 项目 | 详细说明 |
|---|---|
| 核心思想 | 根据小车偏离目标直线的距离修正角速度 |
| 主要输入 | 横向误差、误差积分、误差变化率 |
| 主要公式 | `angular.z = Kp×e + Ki×∫e + Kd×de/dt` |
| 调大什么会更快纠偏 | 增大 `Kp` 或适当增加 `Kd` |
| 适合场景 | 长直线、车辆已经偏离路线 |
| 优点 | 能把车身拉回目标线 |
| 风险 | `Kp` 过大会摆动，`Kd` 过大会放大定位噪声 |
| 使用前提 | 横向误差坐标系和目标直线方向必须正确 |
| 推荐做法 | 先使用 P 控制，确认方向正确后再增加 D 项 |

#### 4. Stanley 控制

| 项目        | 详细说明                                                     |
| --------- | -------------------------------------------------------- |
| 核心思想      | 将航向误差和横向误差同时用于转向                                         |
| 主要输入      | 航向误差、横向误差、线速度、软化速度                                       |
| 典型公式      | `angular.z = yaw_error + atan(K×cross_error/(speed+v0))` |
| 关键参数      | `stanley_k`、`stanley_v0`                                 |
| 调大什么会更快纠偏 | 增大 `stanley_k`                                           |
| 适合场景      | 直线跟随和路径纠偏                                                |
| 优点        | 同时修正车头方向和横向偏移                                            |
| 风险        | 低速时转向过强，必须设置 `v0`                                        |
| 原项目配置     | `xline_follow_controller/config/line.yaml`               |

#### 5. 原地旋转闭环

| 项目 | 详细说明 |
|---|---|
| 核心思想 | 目标角度减当前角度得到角度误差，根据误差控制原地旋转 |
| 主要输入 | 目标角度、当前 IMU 角度、角度误差 |
| 控制方式 | `angular.z = sign(error) × clamp(K×abs(error), min_w, max_w)` |
| 误差较大时 | 使用较高角速度 |
| 接近目标时 | 逐步降低角速度 |
| 达到阈值时 | 发布零角速度并进入下一阶段 |
| 适合场景 | 正方形 90° 转角、指定角度旋转 |
| 原项目配置 | `line.yaml` 的 `rotation.max_w`、`min_w`、`factor` |
| 注意事项 | 原地旋转不能用位置点运动方向判断航向 |

#### 6. 圆形路径前馈角速度

| 项目 | 详细说明 |
|---|---|
| 核心思想 | 先根据半径和线速度计算理论角速度，再叠加反馈纠偏 |
| 理论公式 | `angular.z = linear.x / radius` |
| 示例 | 半径 `0.2 m`、速度 `0.1 m/s` 时理论角速度为 `0.5 rad/s` |
| 反馈部分 | 叠加航向误差和半径误差修正 |
| 适合场景 | 圆形和圆弧划线 |
| 风险 | 半径、线速度或坐标系错误会直接造成圆形偏差 |
| 原项目配置 | `rpp_circle.yaml` 和 `circle_path_strategy.cpp` |

### 二、两点无障碍导航方法

#### 1. 先转向再直行

| 项目 | 详细说明 |
|---|---|
| 输入 | 起点 `(x0,y0)`、终点 `(x1,y1)`、当前航向 |
| 目标航向 | `atan2(y1-y0, x1-x0)` |
| 执行顺序 | 计算方向 → 原地旋转 → 直线行驶 → 到点停车 |
| 优点 | 逻辑最简单，最容易调试 |
| 缺点 | 直行阶段不纠偏时会逐渐走歪 |
| 适用 | 两点短距离、空旷地面 |
| 推荐改进 | 直行期间加入航向误差和横向误差纠正 |

#### 2. 直线航迹闭环

| 项目 | 详细说明 |
|---|---|
| 输入 | 起点、终点、当前全站仪位置、当前航向 |
| 计算内容 | 横向误差、航向误差、目标点距离 |
| 控制公式 | `angular.z = K_yaw×yaw_error + K_cross×cross_error` |
| 优点 | 能保持小车沿指定直线行驶 |
| 缺点 | 需要可靠的位置和航向反馈 |
| 适用 | CAD 直线划线 |
| 推荐反馈 | 全站仪位置 + IMU 航向 |

#### 3. Pure Pursuit 两点跟踪

| 项目 | 详细说明 |
|---|---|
| 输入 | 直线段、前瞻距离、当前位姿 |
| 输出 | 曲率和角速度 |
| 优点 | 代码成熟，能扩展到曲线 |
| 缺点 | 短直线时前瞻距离需要特别调节 |
| 参数影响 | 前瞻距离小，纠偏快；前瞻距离大，运动平滑 |
| 适用 | 两点直线和连续路径 |

#### 4. Stanley 两点导航

| 项目   | 详细说明                     |
| ---- | ------------------------ |
| 输入   | 目标直线、当前位置、当前航向、当前速度      |
| 输出   | 角速度                      |
| 优点   | 对直线横向偏差修正较强              |
| 缺点   | 低速时需要速度软化项               |
| 适用   | 小车中途走歪后回到目标线             |
| 关键参数 | `stanley_k`、`stanley_v0` |

#### 5. PID 点到点导航

| 项目 | 详细说明 |
|---|---|
| 输入 | 目标位置误差、目标航向误差 |
| 线速度 | 根据目标点距离误差计算 |
| 角速度 | 根据航向误差计算 |
| 优点 | 实现简单，适合短距离 |
| 缺点 | 只看目标点时可能走弧线，不保证严格贴直线 |
| 改进 | 增加目标直线横向误差项 |

#### 6. 梯形速度规划

| 阶段 | 控制方式 | 目的 |
|---|---|---|
| 加速段 | 逐渐增加 `linear.x` | 减少启动冲击 |
| 匀速段 | 保持目标速度 | 稳定行驶 |
| 减速段 | 按剩余距离降低速度 | 减少冲过终点 |
| 停车段 | 发布零速度并确认 | 清除旧速度 |

### 三、航向纠正方法

#### 1. IMU 陀螺仪航向纠正

| 项目 | 详细说明 |
|---|---|
| 测量量 | `gyro_z` 角速度 |
| 计算方法 | 对角速度按时间积分 |
| 基本关系 | `yaw_new = yaw_old + (gyro_z - bias)×dt` |
| 优点 | 高频、连续、适合原地旋转 |
| 缺点 | 零偏导致长时间漂移 |
| 必要处理 | 静止零偏采样、角度归一化、异常值过滤 |
| 适合阶段 | 原地旋转、短时转弯、外部定位短暂中断 |

#### 2. 轮速航程差纠正

| 项目 | 详细说明 |
|---|---|
| 输入 | 左轮位移、右轮位移、轮距 |
| 计算方法 | 根据左右轮行程差计算航向变化 |
| 基本关系 | `delta_yaw = (delta_s_right-delta_s_left)/wheel_base` |
| 优点 | 不依赖外部设备，运动连续 |
| 缺点 | 打滑、轮径误差、轮距误差会积累 |
| 适合阶段 | 连续行驶、短时间位置预测 |
| 不适合 | 依靠轮速判断原地旋转绝对角度 |

#### 3. 全站仪位置点航向纠正

| 项目 | 详细说明 |
|---|---|
| 输入 | 连续棱镜坐标 `x,y` |
| 计算方法 | `atan2(y_current-y_previous, x_current-x_previous)` |
| 优点 | 可长期校正 IMU 和轮速漂移 |
| 缺点 | 棱镜遮挡、坐标过期、位置噪声会影响结果 |
| 更新条件 | 坐标有效、时间戳递增、位移超过最小阈值 |
| 适合阶段 | 直线中段、圆形轨迹、实际划线误差测量 |
| 不适合 | 原地旋转或几乎没有位移的阶段 |

#### 4. 直线拟合航向

| 项目 | 详细说明 |
|---|---|
| 输入 | 一段时间内多个有效位置点 |
| 计算方法 | 对位置点进行直线拟合，取拟合线方向 |
| 优点 | 比单纯两点方向更抗噪声 |
| 缺点 | 需要积累足够数量的位置点 |
| 适合阶段 | 长直线划线 |
| 风险 | 轨迹本身是曲线时不能强行直线拟合 |

#### 5. 视觉里程计航向

| 项目 | 详细说明 |
|---|---|
| 输入 | 相机图像、特征点或光流 |
| 输出 | 相邻图像之间的姿态变化 |
| 优点 | 可估计位置和航向变化 |
| 缺点 | 受光照、纹理、地面反光影响 |
| 适合 | 有明显地面纹理的室内外环境 |

#### 6. 激光雷达匹配航向

| 项目 | 详细说明 |
|---|---|
| 输入 | 连续激光扫描、地图或局部点云 |
| 输出 | 扫描间姿态变化或地图中的航向 |
| 优点 | 不受光照影响，可与地图结合 |
| 缺点 | 空旷区域缺少几何特征 |
| 适合 | 有墙面、设备或固定结构的环境 |

#### 7. 多传感器融合

| 方法 | 融合对象 | 特点 | 适合用途 |
|---|---|---|---|
| 互补滤波 | IMU + 外部航向 | 结构简单，实时性高 | 快速工程实现 |
| EKF | IMU、轮速、全站仪、位置 | 可使用噪声模型和协方差 | `robot_pose` 长期稳定估计 |
| UKF | 非线性姿态和位置状态 | 对非线性模型更友好 | 复杂运动模型 |
| 因子图 | 多时刻观测和约束 | 可全局优化轨迹 | 高精度离线或高级定位 |
| 地图匹配 | 实际轨迹与 CAD 路径 | 可利用已知设计路线 | 重复划线任务 |

### 四、速度仲裁与命令链路

#### 1. 输入来源表

| 话题 | 发布来源 | 用途 | 优先级 |
|---|---|---|---:|
| `/task_cmd_vel` | CAD 任务、基础控制器 | 自动导航和划线 | 低于人工遥控 |
| `/tablet_cmd_vel` | 8080 网页后端 | 人工方向键控制 | 高于任务 |
| `/cmd_vel` | 唯一 `cmd_vel_mux` | 发送给轮驱的最终速度 | 最终输出 |

#### 2. 仲裁器安全机制

| 机制 | 作用 | 触发条件 | 结果 |
|---|---|---|---|
| 来源租约 | 防止历史速度永久有效 | 输入超过约定时间未刷新 | 清除来源并发布零速 |
| 软件急停锁存 | 立即禁止速度输出 | `/emergency_stop=true` | 清除来源，持续输出零速 |
| 复位服务 | 建立新的控制会话 | 调用 `/emergency_stop/reset` 且条件满足 | 解除锁存，仍需零速握手 |
| 零速握手 | 防止旧任务突然恢复 | 来源先发送零速度 | 该来源获得新的输入资格 |
| 唯一发布者检查 | 防止多个节点争抢 `/cmd_vel` | 启动时发现已有发布者 | 拒绝重复仲裁器 |
| 持续零速看门狗 | 防止断流后保留旧命令 | 无有效来源、急停或超时 | 周期发布零速度 |

#### 3. 相关状态接口

| 接口 | 类型 | 作用 | 是否直接让车运动 |
|---|---|---|---|
| `/emergency_stop` | `std_msgs/msg/Bool` 话题 | `true` 锁存停车 | 否，只会停车 |
| `/emergency_stop/reset` | `std_srvs/srv/Trigger` 服务 | 解除软件急停 | 否，需要后续新速度 |
| `/cmd_vel_mux/get_status` | `std_srvs/srv/Trigger` 服务 | 查询状态 JSON | 否，只读 |
| `/cmd_vel_mux/status` | `std_msgs/msg/String` 话题 | 周期发布状态 | 否，只读 |

#### 4. 合格运行条件

| 检查项 | 合格条件 |
|---|---|
| 运行服务 | ROS 运行栈处于 `active` |
| 仲裁节点 | 存在唯一 `/cmd_vel_mux` |
| `/cmd_vel` 发布者 | 数量为 1，且节点是 `cmd_vel_mux` |
| `/cmd_vel` 订阅者 | 包含轮驱节点 |
| 急停状态 | 已按现场流程复位，`emergency_stop_latched=false` |
| 来源握手 | 所用来源的 `source_requires_zero=false` |
| 当前输出 | 测试开始前 `linear.x=0`、`angular.z=0` |

#### 5. 最终控制链路

| 顺序 | 节点或话题 | 作用 |
|---:|---|---|
| 1 | CAD / 自动控制器 | 计算路径误差和目标角速度 |
| 2 | `/task_cmd_vel` | 发布任务速度 |
| 3 | `cmd_vel_mux` | 检查来源、优先级、急停和限速 |
| 4 | `/cmd_vel` | 唯一最终速度输出 |
| 5 | `differential_wheels_driver` | 将线速度和角速度转换为左右轮速度 |
| 6 | CAN 电机 | 执行左右轮转速 |

### 五、四个主题的统一选择建议

| 任务 | 推荐组合 |
|---|---|
| 两点直线导航 | 先转向再直行 + 航向误差 + 横向误差 |
| CAD 直线划线 | Stanley 或横向 PID + IMU + 全站仪位置点 |
| 正方形划线 | 直线跟随 + IMU 原地 90° 闭环旋转 |
| 圆形划线 | RPP + `v/r` 前馈 + 全站仪半径误差反馈 |
| 全站仪短暂丢点 | IMU + 轮速短时预测，拒绝使用过期坐标 |
| 多来源速度控制 | `/task_cmd_vel`、`/tablet_cmd_vel` → 唯一 `cmd_vel_mux` → `/cmd_vel` |

### 六、每种方法的具体讲解

#### 1. RPP / Pure Pursuit 曲率法

RPP 不直接把小车拉向终点，而是先在目标路径前方取一个前瞻点，再根据小车当前位置和前瞻点之间的几何关系计算曲率。前瞻距离越小，车辆越快响应路线变化；前瞻距离越大，车辆越平滑。调试时应先确认坐标系、路径方向和前瞻点正确，再调整前瞻距离，不能一开始就大幅提高角速度。

#### 2. 航向误差比例控制

这种方法只关心小车车头是否朝向目标方向。小车偏左或偏右但车头方向正确时，它不会主动修正横向位置，因此适合起步对准和小角度航向修正。调大比例增益会让转向更快，但如果出现左右来回摆动，说明增益过大或反馈数据延迟较大。

#### 3. 横向误差 PID

横向误差 PID 计算小车距离目标直线的垂直距离，并把这个距离转换为转向速度。比例项负责立即拉回路线，积分项用于消除长期偏差，微分项用于抑制变化过快的误差。划线时建议先只启用比例项，确认纠偏方向正确后再少量加入微分项，积分项要设置防积分饱和。

#### 4. Stanley 控制

Stanley 把航向误差和横向误差合成为一个转向量，特别适合小车已经偏离直线的情况。`stanley_k` 决定横向纠偏强度，`stanley_v0` 防止低速时分母过小而导致角速度突然增大。实际调参应观察车辆是否稳定回到直线，以及回线后是否发生左右摆动。

#### 5. 原地旋转闭环

原地旋转闭环先计算目标角度与当前角度的最短角度差，再根据剩余误差控制左右轮反向转动。距离目标角度较远时允许较快旋转，接近目标时必须降低角速度，达到角度容差后立即发布零速度。该方法需要可靠的 IMU 航向，不能用几乎不变化的位置点推算原地旋转角度。

#### 6. 圆形路径前馈角速度

圆形路径的理论角速度由线速度除以半径得到，前馈项可以让车辆先具备正确的圆周运动趋势。之后再用航向误差和实际半径误差进行反馈修正。如果圆形整体偏大或偏小，应先检查半径和线速度，再调整反馈增益，不能只提高角速度上限。

#### 7. 先转向再直行

这是两点导航最容易验证的流程。小车先根据起点和终点计算目标航向，原地转到目标方向后将角速度降为零，再沿直线前进。它适合验证底盘基本运动，但直行时仍需要低增益航向纠偏，否则左右轮速度差和地面摩擦会让车辆逐渐偏离路线。

#### 8. 直线航迹闭环

直线航迹闭环不仅检查小车离终点还有多远，还检查小车偏离目标直线多少。控制器把横向误差和航向误差分别计算后合成为角速度，因此能够在行驶中把车拉回设计线。全站仪坐标必须新鲜且时间戳递增，否则闭环可能根据旧位置反复修正。

#### 9. Pure Pursuit 两点跟踪

把起点到终点看成一条路径后，Pure Pursuit 会不断寻找这条线前方的目标点。它比单纯“朝终点转向”更稳定，但短线段中前瞻距离占路线长度的比例较大，容易出现提前转向或终点附近切角。短距离测试时应限制前瞻距离，并单独设置到点停车阈值。

#### 10. Stanley 两点导航

Stanley 两点导航适合小车在直线中途发生偏移的情况。它会根据车辆当前速度自动调整横向纠偏强度，低速时通过软化项避免转向过猛。使用时必须保证横向误差的正负号定义正确，否则小车会越纠越偏。

#### 11. PID 点到点导航

PID 点到点导航根据终点距离控制线速度，根据终点方向控制角速度。它适合短距离移动和功能验证，但如果只使用终点误差，车辆可能走弧线到达终点，不能保证中途经过指定直线。因此 CAD 划线应在点到点 PID 外再加入目标直线横向误差。

#### 12. 梯形速度规划

梯形速度规划把一次运动分成加速、匀速、减速和停车四段。它可以降低起步冲击和终点冲过量，适合较长直线。对于很短的路线，车辆可能还没有达到匀速就需要减速，此时实际速度曲线会退化为三角形速度曲线。

#### 13. IMU 陀螺仪航向纠正

IMU 通过测量绕垂直轴的角速度并积分得到航向变化。它的优点是更新快，适合原地旋转和短时间转弯；缺点是零偏会导致角度随时间漂移。使用前应进行静止零偏采样，并在软件中检查数据新鲜度、异常跳变和角度归一化。

#### 14. 轮速航程差纠正

差速车左右轮走过的距离不同，就会产生航向变化。控制器可以根据左右轮位移差和轮距估计车辆转过的角度。该方法连续性好，但轮胎打滑、轮径不准和轮距测量误差都会积累，所以更适合作为短时间预测，不能单独作为长期绝对航向。

#### 15. 全站仪位置点航向纠正

全站仪连续测得棱镜坐标后，可以用相邻位置点连线方向估计车辆运动方向。这种方法能够校正 IMU 和轮速的长期漂移，特别适合空旷场地的精密划线。必须过滤过期坐标、无效坐标和位移过小的点，原地旋转时不能依赖这种方法。

#### 16. 直线拟合航向

直线拟合不是只看相邻两个点，而是使用一段时间内的多个有效位置点估计整体运动方向。它对单点噪声更不敏感，适合长直线划线。拟合窗口过短时抗噪能力不足，窗口过长时车辆转弯会出现方向滞后，因此需要按运动阶段调整窗口。

#### 17. 视觉里程计航向

视觉里程计通过连续图像中的特征点、光流或标记物估计相机和车辆的相对运动。它可以补充 IMU 和轮速，但会受到光照变化、地面反光、灰尘和重复纹理影响。使用前要确认相机安装方向和车体坐标系变换正确。

#### 18. 激光雷达匹配航向

激光雷达通过比较连续扫描，或者把扫描与已有地图匹配，得到车辆的位姿变化。它在有墙面、设备和固定结构的环境中比较有效，在完全空旷的地面上缺少可匹配特征。匹配结果应检查质量评分和时间戳，不能无条件接受跳变结果。

#### 19. 多传感器融合

多传感器融合让 IMU 提供高频变化，让轮速提供运动连续性，让全站仪或其他外部定位提供长期校正。EKF 和 UKF 需要正确的噪声参数、坐标变换和时间同步；互补滤波实现更简单，但对复杂运动的表达能力较弱。融合前应先分别验证每个传感器，否则错误数据会被融合器放大成错误的 `robot_pose`。

#### 20. 速度来源仲裁

速度仲裁器接收任务控制和人工遥控的输入，按照优先级、来源新鲜度、急停状态和限速规则选择一个输出。最终 `/cmd_vel` 应只有一个 `cmd_vel_mux` 发布者。诊断时先检查发布者唯一、轮驱订阅、急停状态和零速握手，再发送非零速度。

#### 21. 软件急停与复位

`/emergency_stop` 发布 `true` 后会锁存停车，清除已有速度来源并持续输出零速。`/emergency_stop/reset` 只负责在安全条件满足时建立新的控制会话，不会恢复旧速度；复位后还需要等待冷却并对准备使用的输入话题发送零速握手。

#### 22. `/cmd_vel` 最终输出

控制器不应直接绕过仲裁器发布 `/cmd_vel`。正确链路是任务或网页发布输入话题，`cmd_vel_mux` 统一处理后发布最终速度，轮驱节点订阅最终话题并完成左右轮换算。测试前后都应检查 `/cmd_vel` 发布者数量和当前输出是否为零。
