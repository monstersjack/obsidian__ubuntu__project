### 三、直线划线的误差定义

目标直线由起点和终点确定：

~~~text
dx = x_end - x_start
dy = y_end - y_start
ψ_path = atan2(dy, dx)
~~~

机器人状态为：

~~~text
P_robot = (x_robot, y_robot)
ψ_robot = 当前航向角
~~~

航向误差：

~~~text
e_ψ = normalize_angle(ψ_path - ψ_robot)
~~~

横向误差使用目标直线左法向计算：

~~~text
n = (-sin(ψ_path), cos(ψ_path))
e_y = (P_robot - P_start) · n
~~~

| 误差 | 含义 |
|---|---|
| e_y 大于 0 | 机器人在目标线左侧 |
| e_y 小于 0 | 机器人在目标线右侧 |
| e_ψ 大于 0 | 车头需要向左修正 |
| e_ψ 小于 0 | 车头需要向右修正 |

### 四、直线 PID 航向纠偏

PID 的输出为：

~~~text
ω_PID = Kp·e_ψ + Ki·∫e_ψdt + Kd·de_ψ/dt
~~~

源代码创建并使用航向 PID：

~~~cpp
heading_pid_controller_->compute(yaw_error, dt);
~~~

参数位于 line.yaml：

~~~yaml
heading_pid:
  alignment:
    kp: 1.0
    ki: 0.0
    kd: 0.1
  following:
    kp: 1.0
    ki: 0.0
    kd: 0.1
~~~

项目还设置了积分限幅：

~~~cpp
heading_pid_controller_->setIntegralLimits(-0.05, 0.05);
~~~

当前 Ki 为 0，车辆长期向一侧偏移时，不能只提高 Kp，还要检查轮距、轮径、定位坐标和航向基准。

### 五、直线 Stanley 横向纠偏

Stanley 将航向误差与横向误差结合：

~~~text
δ = e_ψ + atan(k·e_y/(v+v0))
~~~

源代码中的横向截获角：

~~~cpp
double intercept = std::atan2(-k * cross_track_error, v + v0);
~~~

对应参数：

~~~yaml
guidance:
  mode: "weighted_yaw"
  alignment_mode: "stanley"
  following_mode: "weighted_yaw"
  stanley_k: 1.0
  stanley_v0: 0.1
  theta_max: 0.25
~~~

一句话：Stanley 根据“离目标线有多远”和“车头偏了多少”共同决定回线角度。

### 六、直线加权航向模式

项目还支持加权航向：

~~~cpp
final_target_yaw =
    path_ideal_yaw * current_heading_weight
    + path_direction_yaw * target_heading_weight;
~~~

它用于让起点对齐阶段和正常跟随阶段采用不同的航向权重，减少车辆左右摆动。

重要区别：

~~~text
直线控制器 = 横向误差 + 航向误差 → PID/Stanley/加权航向
RPP控制器 = 前瞻点 → 曲率 → 角速度
~~~

当前源代码没有证据表明直线任务会把 PID、Stanley 和 RPP 三个角速度直接相加，而是根据模式选择控制方式。

### 八、曲线划线的几何前瞻

曲线跟随不是只看当前位置，而是查看车辆前方的一段路径：

~~~text
当前位姿
  ↓
裁剪附近路径
  ↓
按照前瞻距离寻找前瞻点
  ↓
计算车辆到前瞻点的角度
  ↓
计算曲率
  ↓
计算角速度
~~~

RPP 主入口：

~~~cpp
RPPController::computeVelocityCommands(...)
~~~

调用顺序：

~~~text
pruneGlobalPlan(...)
getLookAheadDistance(...)
getLookAheadPoint(...)
computeAngleToLookahead(...)
computeCurvature(...)
generateVelocityCommand(...)
~~~

### 九、Pure Pursuit 的原理

Pure Pursuit 把车辆当前位置和前瞻点看成一条几何圆弧，计算车辆应该沿多大曲率转弯。

核心公式：

~~~text
κ = 2·sin(α)/L
ω = v·κ
~~~

源代码核心：

~~~cpp
double curvature =
    2.0 * std::sin(angle_to_lookahead)
    / lookahead_distance;
~~~

随后：

~~~cpp
ctx.pp_angular_velocity =
    desired_velocity * current_curvature_;
~~~

一句话：Pure Pursuit 通过车辆前方的目标点计算应该转多大的弯。

### 十、RPP 的增强内容

| 增强项 | 作用 |
|---|---|
| 曲率约束速度 | 转弯半径越小，线速度越低 |
| 前瞻距离上下限 | 防止前瞻点过近或过远 |
| 角速度平滑 | 防止角速度突变 |
| 位置滤波 | 降低全站仪和 IMU 噪声 |
| 目标接近约束 | 接近终点时调整速度 |
| 路径裁剪 | 只处理车辆附近路径 |

曲线路径参数：

~~~yaml
lookahead:
  time: 0.15
  min_dist: 0.18
  max_dist: 0.18
~~~

默认前瞻距离：

~~~text
L = |v| × lookahead.time
~~~

由于最小值和最大值都为 0.18 m，当前曲线路径实际基本固定为 0.18 m。

### 十一、RPP 曲率约束和速度调整

RPP 先计算曲率半径：

~~~text
radius = 1 / abs(curvature)
~~~

当半径小于限制值时降低速度：

~~~text
scale = radius / regulated_min_radius
v = max(min_velocity, raw_velocity × scale)
~~~

配置：

~~~yaml
tracking:
  regulated_min_radius: 0.5
~~~

一句话：曲线越急，RPP 越主动降速，避免车速过高导致车辆切弯。

### 十二、RPP 角速度滤波

~~~yaml
smoothing:
  type: 'lowpass'
  lowpass:
    gain: 0.9

filter:
  angular:
    lowpass_active: true
    cutoff_freq: 1.5
    sample_rate: 18.0
    rate_limit: 0.03
~~~

滤波太强会导致转向滞后、曲线切弯；滤波太弱会导致角速度抖动和车辆左右摆动。

### 十三、Spline 曲线划线

Spline 路径由多个控制点生成连续曲线，然后交给 RPP：

~~~cpp
rpp_follow_controller_->setPlanForSpline(
    spline_data.vertices,
    spline_data.degree,
    spline_data.start_x,
    spline_data.start_y,
    spline_data.end_x,
    spline_data.end_y);
~~~

一句话：Spline 负责把 CAD 控制点变成连续曲线，RPP 负责让小车跟随这条曲线。

### 十四、圆形划线

圆形路径理论关系：

~~~text
ω_ref = v / r
~~~

| 半径 | 线速度 | 理论角速度 |
|---:|---:|---:|
| 0.20 m | 0.05 m/s | 0.25 rad/s |
| 0.20 m | 0.08 m/s | 0.40 rad/s |
| 0.20 m | 0.10 m/s | 0.50 rad/s |

圆形还要处理圆心、半径、起始切线、路径采样、累计航向角和喷墨开始/停止位置。

### 十五、圆形动态速度和角速度偏差

~~~yaml
circle_dynamics:
  enabled: true
  velocity:
    reference_velocity: 0.05
    reference_radius: 0.3
    radius_exponent: 0.5
    min_velocity: 0.03
    max_velocity: 0.1
  lookahead:
    reference_lookahead: 0.2
    min_dist: 0.2
    max_dist: 0.22
~~~

目标角速度：

~~~text
target_ω = target_v / radius
~~~

圆形策略还会围绕理论角速度限制 RPP 输出：

~~~text
angular_velocity_delta =
    base_omega - baseline_angular_velocity
~~~

配置：

~~~yaml
deviation:
  strict_ratio: 0.05
  relaxed_ratio: 0.05
~~~

优点是半径更稳定，缺点是定位误差较大时纠偏能力不足。

### 十六、LQR 算法原理

LQR 全称为 Linear Quadratic Regulator，中文为线性二次型调节器。

常用状态向量：

~~~text
x = [e_y, e_ψ, de_y/dt, de_ψ/dt]^T
~~~

车辆模型：

~~~text
x_dot = A x + B u
~~~

目标函数：

~~~text
J = ∫(xᵀQx + uᵀRu)dt
~~~

控制律：

~~~text
u = -Kx
~~~

圆形路径通常加入理论前馈：

~~~text
ω_final = v/r - Kx
~~~

一句话：LQR 根据多个误差状态整体计算最优角速度，而不是只看一个前瞻点。

### 十七、LQR 的 Q、R 调参

| 参数 | 增大后的效果 | 可能问题 |
|---|---|---|
| 横向误差权重 | 更积极回到轨迹 | 可能摆动 |
| 航向误差权重 | 更积极修正车头 | 可能转向过猛 |
| 误差变化率权重 | 抑制快速变化 | 响应变慢 |
| R 控制输入权重 | 控制更平滑 | 跟踪误差可能变大 |

LQR 必须建立在正确车辆模型上，轮距、轮径、速度、采样周期和定位延迟都会影响效果。

### 十八、源项目中的 LQR 核查结论

源项目中存在以下引用和调度名称：

~~~cpp
#include <xline_follow_controller/lqr_follow/lqr_circle_controller.hpp>
#include <xline_follow_controller/lqr_follow/lqr_curve_controller.hpp>
~~~

CMakeLists.txt 也引用：

~~~cmake

src/lqr_follow/lqr_curve_controller.cpp
~~~

必须确认以下目录中是否实际存在对应头文件和源文件：

~~~text
ros_pack/xline_follow_controller/include/xline_follow_controller/lqr_follow/
ros_pack/xline_follow_controller/src/lqr_follow/
~~~

真正完整的 LQR 实现通常应能看到：

~~~cpp
Eigen::MatrixXd Q;
Eigen::MatrixXd R;
Eigen::MatrixXd K;
solveRiccati(...);
u = -K * x;
~~~

如果核心文件不存在，准确结论是：

~~~text
源项目有 LQR 调度设计，但 LQR 算法实现不完整或缺失。
~~~

### 十九、四种算法对比

| 算法 | 主要误差 | 是否需要车辆模型 | 适合路径 | 当前源项目情况 |
|---|---|---:|---|---|
| PID | 航向误差及变化率 | 否 | 直线 | 有实现 |
| Stanley | 横向误差和航向误差 | 少量 | 直线、缓曲线 | 有实现 |
| Pure Pursuit | 前瞻点几何误差 | 否 | 曲线、Spline | 通过 RPP 实现 |
| LQR | 多状态误差 | 是 | 圆、曲线、高精度跟踪 | 调用存在，核心需核查 |

### 二十、当前 CAD 划线推荐结构

直线：

~~~text
横向误差 + 航向误差
→ Stanley 或 PID
→ 角速度限幅
→ 角速度平滑
→ /task_cmd_vel
~~~

Spline 或一般曲线：

~~~text
几何前瞻点
→ Pure Pursuit / RPP
→ 曲率约束
→ 角速度平滑
→ /task_cmd_vel
~~~

圆形或圆弧：

~~~text
理论角速度 v/r
→ 横向误差反馈
→ 航向误差反馈
→ 角速度约束
→ /task_cmd_vel
~~~

### 二十一、直线走歪排查表

| 检查项 | 典型现象 | 处理方向 |
|---|---|---|
| /robot_pose 跳变 | 车辆突然大幅修正 | 检查全站仪、IMU 和定位滤波 |
| 横向误差符号反了 | 越纠偏越偏 | 检查左法向和角速度符号 |
| 航向基准错误 | 起步方向就不对 | 检查定轴和四元数转换 |
| stanley_k 太小 | 回线慢 | 适当增加增益 |
| stanley_k 太大 | 左右摆动 | 降低增益或加强滤波 |
| 角速度上限太小 | 纠偏跟不上 | 检查最大角速度 |
| 轮距错误 | 直行逐渐弯曲 | 重新测量左右轮轴中心距 |
| 左右轮径不同 | 一直偏向一侧 | 检查轮径和电机标定 |
| 速度过高 | 纠偏滞后 | 降低线速度或增加反馈 |

### 二十二、曲线切弯排查表

| 检查项 | 典型问题 |
|---|---|
| 前瞻距离过大 | 车辆切弯，轨迹在曲线内侧 |
| 前瞻距离过小 | 车辆左右摆动 |
| 线速度过高 | 角速度跟不上 |
| 角速度滤波过强 | 控制滞后 |
| regulated_min_radius 过大 | 过早降速 |
| 路径点过稀 | 曲线几何不连续 |
| 全站仪数据延迟 | 车辆依据旧位置纠偏 |
| 轮距不准 | 理论角速度与实际转弯半径不一致 |
| 喷墨 TF 错误 | 车辆轨迹正确但墨线偏移 |

### 二十三、最终结论

1. 源项目直线控制主要是 PID、Stanley 和加权航向。
2. 源项目 Spline 和一般曲线明确采用 RPP 结构。
3. RPP 的核心是前瞻点、曲率和 ω=vκ。
4. 圆形路径的理论角速度是 ω=v/r。
5. RPP 不是只看当前位置，而是看前方几何点。
6. 直线控制和 RPP 是不同控制器，不应默认把角速度直接相加。
7. LQR 在源项目中有调度名称和 CMake 引用，但必须确认 lqr_follow 核心文件是否完整。
8. 直线走歪时，应先检查 /robot_pose、横向误差符号、轮距、轮径和速度限幅。
9. 曲线切弯时，应先检查前瞻距离、速度、滤波和路径点密度。
10. CAD 划线精度由算法、定位、轮驱、速度仲裁和喷墨 TF 共同决定。
