# 电脑设置
### 电脑设置一个小时不操作就息屏,在过一个小时就休眠

```bash
# 1. 60分钟无操作 自动息屏+锁屏
gsettings set org.gnome.desktop.session idle-delay 3600
gsettings set org.gnome.desktop.screensaver lock-enabled true
gsettings set org.gnome.desktop.screensaver lock-delay 0

# 2. 息屏后60分钟 自动休眠（完全断电不耗电，比关机更安全）
gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-ac-timeout 3600
gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-ac-type 'hibernate'
gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-battery-timeout 3600
gsettings set org.gnome.settings-daemon.plugins.power sleep-inactive-battery-type 'hibernate'

# 3. 电源键 = 息屏+锁屏（原生支持，无任何报错）
sudo sed -i 's/#HandlePowerKey=poweroff/HandlePowerKey=lock/' /etc/systemd/logind.conf
sudo systemctl restart systemd-logind
```

### 提示词

不要影响我电脑的安全和稳定，不要影响读取u盘，读取输入设备，把那些服务检测还有比较长时间等待的服务判定关闭掉。

目标：
- 缩短 Ubuntu 系统关机时间
- 保持系统安全和稳定
- 保留对以下核心功能的支持：
	- U盘/移动存储设备读取
	- USB 外设（键盘、鼠标、手写板等）
	- 输入法（fcitx5、GNOME 输入法）
	- 显示/多屏显示功能
	- 网络基础功能（网络管理器、WiFi、VPN）
- 不卸载系统关键组件
- 只关闭或优化那些在关机过程中等待较长时间且可安全屏蔽的用户级服务

优化内容：
1. 检测关机过程中超时服务：
	- 使用 `journalctl -b -1 | grep -E "Stopping|Timeout|timed out"` 查找关机等待时间长的服务
	- 仅针对用户级服务，排除核心系统服务（udisks2, NetworkManager, systemd-logind, display-manager 等）
2. 用户级慢服务优化：
	- Evolution 地址簿、日历、邮件相关服务
	- Tracker 文件索引服务（tracker-miner-fs-3, tracker-extract-3, tracker-writeback-3）
	- GNOME Keyring SSH 代理（gnome-keyring-ssh）
	- Flatpak session helper / xdg 权限服务
	- GNOME 软件更新服务（gnome-software-service）
	- GNOME 初始设置和帮助服务（gnome-initial-setup, yelp）
3. 优化措施：
	- 对可屏蔽的服务执行 `systemctl --user mask service_name.service`
	- 设置服务超时：

		```
        mkdir -p ~/.config/systemd/user/service_name.service.d/
        echo -e "[Service]\nTimeoutStopSec=1s" > ~/.config/systemd/user/service_name.service.d/timeout.conf
        systemctl --user daemon-reload
        ```

	- 全局系统关机超时配置：

		```
        sudo nano /etc/systemd/system.conf
        # 添加或修改：
        DefaultTimeoutStopSec=3s
        sudo systemctl daemon-reload
        ```

4. 保留关键服务和硬件：
	- 不屏蔽 udisks2（U盘和存储设备）
	- 不屏蔽 systemd-logind（输入设备、会话管理）
	- 不屏蔽 NetworkManager（网络管理）
	- 不屏蔽 display-manager / Xorg / Wayland（显示和多屏）
5. 验证优化效果：
	- `systemctl --user list-unit-files | grep -E "tracker|evolution|flatpak|xdg|gnome-software"`
	- `journalctl -b -0 | grep -i "timed out\|stop"` 查看关机超时是否减少
	- 确认 U盘、输入法、显示、网络功能正常

### 电脑提升开机速度的指令

```shell
# 禁用NetworkManager等待网络（最常见启动慢原因）
sudo systemctl disable NetworkManager-wait-online.service

# 禁用snapd服务（不使用Snap应用可关闭，启动极慢）
sudo systemctl disable --now snapd snapd.socket snapd.seeded.service

# 禁用ModemManager（无4G/移动网卡可关闭）
sudo systemctl disable --now ModemManager

# 禁用avahi-daemon（局域网设备发现服务）
sudo systemctl disable --now avahi-daemon

# 禁用apport崩溃报告服务
sudo systemctl disable --now apport

# 禁用fwupd固件更新服务（可手动运行）
sudo systemctl disable --now fwupd

# 完全屏蔽e2scrub磁盘扫描等待服务（防止被其他程序意外启动）
sudo systemctl mask e2scrub_reap.service
```

```bash
# 第一步：修改GRUB引导等待时间从10秒为1秒，减少开机等待耗时
sudo sed -i 's/^GRUB_TIMEOUT=.*/GRUB_TIMEOUT=1/' /etc/default/grub && sudo update-grub

# 第二步：禁用gpu-manager开机自检，减少启动耗时（按需切换模式下不影响显卡使用）

# 第三步：禁用networkd-dispatcher开机自启（NetworkManager已够用，无需额外服务）

sudo systemctl disable thermald.service

# 第三步：禁用cups打印服务（无打印机可关闭，需要时可手动启动）
sudo systemctl disable cups.service cups-browsed.service

# 第三步：禁用bluetooth开机自启（用到时系统会自动按需启动）
sudo systemctl disable bluetooth.service

# 第三步：禁用kerneloops内核错误上报服务（日常使用无需）
sudo systemctl disable kerneloops.service

# 第三步：禁用secureboot-db服务（Secure Boot已关闭，此服务无用）
sudo systemctl disable secureboot-db.service

# 第三步：禁用openvpn自动连接服务（不用VPN自动连接可关闭）
sudo systemctl disable openvpn.service

# 第四步：修改systemd关机超时为5秒，加快关机速度
sudo sed -i 's/^#DefaultTimeoutStopSec=.*/DefaultTimeoutStopSec=5s/' /etc/systemd/system.conf

# 第四步：修改systemd启动超时为10秒，优化启动流程
sudo sed -i 's/^#DefaultTimeoutStartSec=.*/DefaultTimeoutStartSec=10s/' /etc/systemd/system.conf

# 第四步：确保DefaultTimeoutStopSec配置写入文件（避免原配置不存在）
grep -q "^DefaultTimeoutStopSec" /etc/systemd/system.conf || echo "DefaultTimeoutStopSec=5s" | sudo tee -a /etc/systemd/system.conf

# 第四步：确保DefaultTimeoutStartSec配置写入文件（避免原配置不存在）
grep -q "^DefaultTimeoutStartSec" /etc/systemd/system.conf || echo "DefaultTimeoutStartSec=10s" | sudo tee -a /etc/systemd/system.conf

# 第四步：重新加载systemd配置，使超时设置生效
sudo systemctl daemon-reload
```

## Ubuntu 微信增强静默自启完整方案（自动登录+启动后自动后台）
#### 方案概述
本方案在微信原生自动登录基础上，实现**开机无感知启动、自动完成登录、登录后自动最小化到系统托盘**，全程无弹窗打扰，不影响桌面使用。

---

#### 前置说明
- **适用版本**：Linux 原生微信（非Flatpak版）
- **核心原理**：
  1. 利用微信原生"自动登录该设备"授权实现免扫码登录
  2. 使用`xdotool`模拟键盘操作自动点击"进入微信"按钮
  3. 登录完成后自动关闭主窗口，仅保留系统托盘图标
- **安全性**：所有操作均在本地完成，不涉及任何第三方服务，完全安全

---

#### 第一步：环境准备与清理

```bash
# 1. 更新系统包列表
sudo apt update

# 2. 安装xdotool工具（用于模拟键盘鼠标操作，仅需安装一次）
sudo apt install -y xdotool

# 3. 彻底清理微信残留锁文件（解决之前的大量报错）
rm -rf ~/.xwechat/crashinfo/pending/*.lock

# 4. 删除所有之前存在的微信自启动文件（避免冲突）
rm -f ~/.config/autostart/wechat*.desktop
```

---

#### 第二步：创建增强静默自启动配置文件

```bash
# 创建用户自启动目录（如不存在则自动创建）
mkdir -p ~/.config/autostart

# 打开编辑器创建自启动配置文件
nano ~/.config/autostart/wechat-silent.desktop
```

**将以下内容完整粘贴到编辑器中**（按`Ctrl+O`保存，按`Enter`确认文件名，按`Ctrl+X`退出）：

```ini
[Desktop Entry]
Type=Application
Name=微信静默自启
Comment=开机自动启动微信，自动登录并最小化到系统托盘
# 完整执行流程：等待系统加载→启动微信→等待窗口出现→按回车登录→等待登录完成→关闭主窗口
Exec=bash -c "sleep 5 && wechat & sleep 10 && xdotool search --onlyvisible --name '微信' windowactivate --sync key Return && sleep 3 && xdotool search --onlyvisible --name '微信' windowclose"
Hidden=false
NoDisplay=false
X-GNOME-Autostart-enabled=true
StartupNotify=false
Terminal=false
Icon=wechat
```

---

#### 第三步：配置微信自动登录授权（关键步骤）

```bash
# 启动微信进行首次授权配置
wechat
```

**手动操作步骤（仅需执行一次）：**
1. 手机扫码登录微信
2. **手机端务必勾选"自动登录该设备"选项**（这是自动登录的核心授权）
3. 电脑端微信登录成功后，点击左下角三条横线 → 选择"设置"
4. 在"通用设置"中，**取消勾选"开机自动启动微信"**（避免与我们的自定义脚本冲突）
5. 关闭微信主窗口，完成配置

#### 配置文件详解（Exec行逐段解析）

```bash
bash -c "sleep 5 && wechat & sleep 10 && xdotool search --onlyvisible --name '微信' windowactivate --sync key Return && sleep 3 && xdotool search --onlyvisible --name '微信' windowclose"
```

| 部分 | 作用说明 |
| :--- | :--- |
| `sleep 5` | 等待系统桌面完全加载，避免微信启动时桌面环境未就绪 |
| `wechat &` | 后台启动微信，不阻塞后续命令执行 |
| `sleep 10` | 等待微信窗口完全打开并加载完成 |
| `xdotool search --onlyvisible --name '微信'` | 查找标题为"微信"的可见窗口 |
| `windowactivate --sync` | 激活找到的微信窗口，等待激活完成 |
| `key Return` | 模拟按下回车键，点击"进入微信"按钮 |
| `sleep 3` | 等待登录过程完成，主界面完全加载 |
| `windowclose` | 关闭微信主窗口，仅保留系统托盘图标 |

#### 参数微调指南
如果出现自动登录失败或窗口操作异常，可根据你的电脑性能和网络情况调整以下延时参数：

| 参数 | 默认值 | 调整建议 |
| :--- | :--- | :--- |
| 第一个`sleep 5` | 5秒 | 性能较差的电脑可改为8-10秒 |
| 第二个`sleep 10` | 10秒 | 网络慢或微信启动慢可改为12-15秒 |
| 第三个`sleep 3` | 3秒 | 登录过程慢可改为4-6秒 |

## 双系统 GRUB 引导设置

**适用场景**：EFI引导的双系统电脑，希望开机显示GRUB菜单，15秒无操作自动进入Windows，同时保留手动选择Ubuntu的能力。

---

### 核心最终配置（已验证正确）

```ini
# 默认启动项（精确匹配Windows启动项名称，不受内核更新影响）
GRUB_DEFAULT="Windows Boot Manager (on /dev/nvme1n1p1)"

# 显示完整GRUB菜单（不要用hidden，否则无法手动选择系统）
GRUB_TIMEOUT_STYLE=menu

# 菜单倒计时15秒
GRUB_TIMEOUT=15
```

---

### 详细操作步骤
### 1. 确认Windows启动项准确名称（关键！避免路径错误）

```bash
# 查看GRUB检测到的所有Windows启动项
grep "Windows Boot Manager" /boot/grub/grub.cfg
```

**输出示例**（复制单引号内的完整名称）：

```
menuentry 'Windows Boot Manager (on /dev/nvme1n1p1)' --class windows --class os $menuentry_id_option 'osprober-efi-XXXX-XXXX' {
```

### 2. 编辑GRUB主配置文件

```bash
sudo nano /etc/default/grub
```

### 3. 修改对应参数
找到以下三行，替换为核心配置中的内容：
- 将 `GRUB_DEFAULT=0` 改为 `GRUB_DEFAULT="Windows Boot Manager (on /dev/nvme1n1p1)"`
- 将 `GRUB_TIMEOUT_STYLE=hidden` 改为 `GRUB_TIMEOUT_STYLE=menu`
- 将 `GRUB_TIMEOUT=10` 改为 `GRUB_TIMEOUT=15`

**保存退出**：按 `Ctrl+O` → 按 `Enter` 确认文件名 → 按 `Ctrl+X`

### 4. 更新GRUB配置（使设置永久生效）

```bash
sudo update-grub
```

### 5. 验证配置是否正确

```bash
grep -E "GRUB_DEFAULT|GRUB_TIMEOUT_STYLE|GRUB_TIMEOUT" /etc/default/grub
```

**正确输出**：

```
GRUB_DEFAULT="Windows Boot Manager (on /dev/nvme1n1p1)"
GRUB_TIMEOUT_STYLE=menu
GRUB_TIMEOUT=15
```

## vscode
在 2026 年，VS Code 的 AI 注释功能已经从简单的“自动补全”进化到了“意图感知”和“实时纠错”的阶段。这主要通过 GitHub Copilot、Cursor 以及各大厂商的 AI 插件（如 Codeium、Cline 等）实现。

以下是目前 VS Code 实现“注释提示”与“大模型矫正”的核心机制对比：

### VS Code AI 注释功能概览

| 功能模块                     | 实现方式                       | 核心作用                                          | 大模型纠正机制                                           |
| ------------------------ | -------------------------- | --------------------------------------------- | ------------------------------------------------- |
| **行内自动补全 (Ghost Text)**  | 基于上下文的流式预测                 | 当你输入 `//` 时，自动预测你想要写的注释内容。                    | 实时对比上下文代码，若注释逻辑与代码不符，AI 会自动调整建议。                  |
| **行内对话 (Inline Chat)**   | 快捷键 `Ctrl + I` (Win/Linux) | 选中代码或直接在空白行通过自然语言要求 AI 生成或修改注释。               | 支持“二次微调”，AI 会检查注释语法、清晰度，并根据最新代码逻辑修正描述。            |
| **智能纠错 (Smart Actions)** | 右键菜单 / 灯泡图标                | 自动识别模糊、陈旧或错误的注释，并提供一键修复选项。                    | 利用 LLM 的语义分析，检测“注释与代码失配” (Code-Comment Mismatch)。 |
| **文档生成命令**               | `/doc` 指令                  | 针对函数或类自动生成符合规范的标准文档注释（如 JSDoc, Google Style）。 | 严格遵守语言规范，自动修正参数描述、类型标注和返回值信息。                     |

| 操作功能                  | Windows / Linux 快捷键      | 说明                                            |
| :-------------------- | :----------------------- | :-------------------------------------------- |
| **打开侧边对话栏**           | `Ctrl + Alt + I`         | 在侧边栏（默认右侧或左侧）打开 Copilot 聊天窗口。                 |
| **打开/隐藏次要侧边栏**        | `Ctrl + Alt + B`         | 切换显示 VS Code 右侧的“次要侧边栏” (Secondary Side Bar)。 |
| **内联聊天 (Inline)**     | `Ctrl + I`               | 在代码行内直接弹出对话框（用于修改或生成代码）。                      |
| **快速聊天 (Quick Chat)** | `Ctrl + Shift + Alt + L` | 顶部弹出的悬浮式对话框，不占用侧边栏空间。                         |
| **清空当前对话**            | `Ctrl + L` (焦点在聊天框时)     | 快速开启新一轮对话，清除旧的历史记录。                           |

### 核心技术细节

#### 1. 实时提示与预测

现在的 VS Code 插件（尤其是 **GitHub Copilot**）不再只是等待你写完注释，而是在你敲下第一个单词时就开始预测。

* **上下文感知**：AI 不仅看当前行，还会扫描整个项目的代码仓库、打开的标签页（Neighbors Files）以及你的编码习惯，从而生成极高准确度的注释提示。

#### 2. 大模型如何进行“矫正”

“矫正”是 2025-2026 年 AI 助手的重大进步，主要体现在以下两个方面：

* **双向同步校验**：如果你修改了代码逻辑但没改注释，现代 AI 助手（如 **Cursor** 或 **Copilot Edits**）会在编辑器边缘显示弱提醒（如波浪线或淡色图标），提示注释已过时。
* **Prompt 优化重写**：当你在 Inline Chat 中输入一段粗略的注释意图时，AI 会先将其转化为更精准的系统提示词（Prompt Refining），然后再生成高质量的正式文档。

#### 3. 常见快捷操作建议

* **快速修正注释**：选中一段注释，按 `Ctrl + I`，输入“Make this more professional”或“Fix grammar”，大模型会立即提供重写建议。
* **注释生成代码**：写下 `// 获取当前时间并格式化为 YYYY-MM-DD`，按 `Tab` 键，AI 矫正后的代码将直接填充。
