第二步，


我后续准备重新写轮子驱动包。原来的 `wheels_driver` 是基于 iWMC 伺服轮和 CANopen 协议的，现在硬件换成 M1505A/B 电机，所以整体思路是保留 ROS2 上层接口，比如 `/cmd_vel`、`/odom`、`/joint_states` 和 TF，但是底层通信层要改成 M1505A/B 自己的 CAN 协议。

硬件方面，我不使用 USB 转 CAN，而是使用香橙派 5 Plus 的 40Pin CAN 接口。因为香橙派 40Pin 输出的是 ==CAN 控制器的 TX/RX 信号，不能直接接电机的 CAN_H 和 CAN_L，所以中间需要加 ISO1050 CAN 隔离收发模块。==香橙派的 CAN0_TX 和 CAN0_RX 接 ISO1050 的 TXD 和 RXD，ISO1050 的 CANH 和 CANL 再接两个电机的 CAN_H 和 CAN_L。两个电机的红黑电源线单独接 24V 电源，不经过香橙派。

软件方面，第一步先在香橙派系统中启用 `can0`，并设置 CAN 波特率为 1Mbps，因为 M1505A/B 电机默认使用 CAN2.0 标准帧，波特率是 1Mbps。然后安装 `can-utils`，用 `candump` 和 `cansend` 先验证 CAN 总线是否能正常收发。这个阶段先不写 ROS 节点，先保证硬件通信通了。

第二步是确认两个电机的 ID。计划将左轮设置为 ID 1，右轮设置为 ID 2。如果两个电机默认 ID 相同，需要先单独连接一个电机进行 ID 设置，避免总线上 ID 冲突。

第三步开始写 ROS2 驱动包。驱动包中会分几个模块：`socketcan_comm.py` 负责 Linux SocketCAN 通信，打开 `can0` 并发送、接收 CAN 帧；`m1505_protocol.py` 负责封装 M1505A/B 的协议，比如设置速度环模式、发送速度指令、解析反馈帧；`diff_drive_kinematics.py` 负责差速运动学，把 `/cmd_vel` 转换成左右轮目标 RPM；`odometry.py` 负责根据左右轮反馈速度或位置积分里程计；`run_motor.py` 作为主节点，负责订阅、控制循环、发布里程计和安全保护。

控制流程是：ROS2 节点订阅 `/cmd_vel`，得到线速度和角速度后，通过差速运动学计算左右轮速度，再转换成电机协议中的速度给定值。M1505A/B 的速度给定范围是 `-5000` 到 `5000`，对应 `-500RPM` 到 `500RPM`，所以可以用 `raw_speed = rpm * 10` 转换。然后通过 CAN 标识符 `0x32` 控制 ID 1 到 ID 4 的电机。电机反馈帧使用 `0x96 + 电机ID`，里面包含速度、电流、位置、故障和当前模式，驱动需要解析这些信息用于里程计和状态监控。

安全方面会加入几个保护：首先是 `/cmd_vel` 超时保护，如果一段时间没有收到速度指令，就自动发送 0 速度停车；其次是最大线速度、最大角速度和最大电机 RPM 限制，避免一开始速度过大；还会加入左右轮方向反转参数，因为实际装车后可能需要调整左右轮正反方向。节点退出时也要主动发送 0 速度，保证电机停下。

调试顺序会比较保守。先让轮子架空，测试 CAN 通信、设置速度环、单独控制左轮低速转动、单独控制右轮低速转动，再测试两个轮子一起前进、后退和原地转向。确认方向和速度都正常后，再落地进行低速测试。最后再完善 `/odom`、`/joint_states` 和 `odom -> base_link` 的 TF 发布。

整体目标是先实现一个稳定、安全、可调试的底盘驱动节点，让上层仍然通过 `/cmd_vel` 控制机器人，而底层改为直接通过香橙派 40Pin CAN 和 M1505A/B 电机通信。
